## 每天的操作

1. 打开“今日工作台”，从“待核实需求”进入客户。查看原文、AI 判断、未知事项和联系方式证据；有效或不匹配都填写判断理由。
2. 先在“待补联系方式”处理已确认有需求但没有已核实联系路径的客户。GitHub Issue 可按需查询作者公开资料（邮箱、网站、填写的单位）；这只是研究线索，不证明本人身份、商务授权或网站归属。核对原文、作者与机构的关联、官方网站联系页后，将明确的商务或授权联系路径连同证据链接和说明手工录入，再由所有者核实。公开讨论链接不等于商务联系方式。
3. “待你联系”只显示需求有效、尚未联系且有已核实联系路径的客户。客户列表可按已核实、待核实、仅有公开讨论入口和暂无路径筛选；效果统计分别显示候选联系信息和已核实可联系数。邮件地址必须核实才可用于原有邮件草稿流程。
4. 生成并编辑招呼语，复制到你实际使用的客户端。复制不会发送，也不会授权系统发送。完成沟通后在客户页手工记录发生时间、渠道与内容。
5. 设置下次跟进时间，届时进入“到期跟进”；收到客户回复后记录为收到回复，并从“待处理回复”处理。拒绝、不匹配或结束会停止后续提醒。
6. 注册、首次调用、付费、持续使用等暂时手工记录实际业务事件。“效果统计”按客户去重计算；手工回复率按同一客户同时有手工联系与收到回复记录计算，外部消息尚未自动同步。只修改阶段名称不会增加转化数字。优先评估已核实可联系数和手工回复，而不是采集条数；未经样本验证不盲目扩大来源。

## 自动采集与模型

服务器每小时执行公开来源采集和最多 2 条新候选分析，不需要电脑常开。GitHub 已验证；V2EX 当前服务器网络受阻，渠道页显示真实失败原因。微信、QQ、邮件客户端收件尚未接通，需手动记录，不能当作实时统一收件箱。

在“渠道状态”调整关键词/排除条件、暂停来源或申请同步；一小时冷却限制可避免重复点击消耗请求。候选不等于有效商机，技术讨论也可能被初筛收录，需要人工标注。

在“成本与配置”添加或修改模型服务、模型名、密钥及估算单价。先保存，再验证模型列表，最后启用。修改后旧验证失效；已产生的异常模型调用不会自动重试。密钥不回显，不进入 Git。价格仅用于预算估算，实际账单以供应商为准。

真实自动发送仍关闭且队列暂停。原有逐条消息审核流程保留；本轮不会代你确认、发送或自动回复。当前 IP 为 HTTP，尚未配置 HTTPS。
